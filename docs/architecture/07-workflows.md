# 07 工作流

平台包含四类工作流：瀑布开发、功能追加、Bug 修复与自我升级。

## 7.1 瀑布开发工作流

见 [05-orchestration.md](05-orchestration.md) 的状态机定义。流程为：

```
[需求分析] ──人工确认──→ [系统设计] ──人工确认──→ [编码实现] ──人工确认──→ [测试验证] ──人工确认──→ [交付]
    ↑                                                              ↓
    └──────────────────────── 变更回退（人工触发）───────────────────┘
```

## 7.2 功能追加 & Bug 修复（双轨模式）

| 模式 | 触发 | 工作流 | 权限 |
|-----|------|--------|------|
| **功能追加** | Web 端需求单 | 完整瀑布流 | 需全阶段审核 |
| **Bug 修复** | 告警/工单 | 定位→复现→修复→回归 | 修复方案 + 回归结果双审核 |

### Bug 修复流水线

```
Bug 报告 → 相似 Bug 检索(历史库) → 根因分析(LLM) → 生成补丁 → 本地测试
   ↑                                                              ↓
   └────────────── 审核通过合并 ← 人工审核 ← 测试报告 ──────────────┘
```

## 7.3 自我升级模块（元能力）

```
自我升级循环：
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│ 执行日志分析 │ →  │ 策略优化建议 │ →  │ 配置热更新   │
│ (成功率统计) │     │ (LLM 反思)   │     │ Prompt/Skill │
└─────────────┘     └─────────────┘     └─────────────┘
       ↑                                      ↓
       └────────── 效果验证(A/B 对比) ─────────┘
```

### 升级管控

- **Prompt 版本化**：存 Git，升级即提 MR，需人工审批
- **Skill 扩展**：pi.dev 的 TypeScript 扩展，版本化管控
- **工具权重优化**：根据历史成功率动态调整工具选择
- 升级配置双人审批 + 灰度发布
